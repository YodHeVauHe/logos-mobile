# Architecture Decision Records

ADRs record evidence-backed decisions that affect component boundaries, platform integration, or interfaces used by later phases. The roadmap and issue checklists track progress; this directory records why an architectural choice was made.

## Statuses

- **Proposed:** evidence and alternatives are documented; review is pending.
- **Accepted:** the decision was reviewed and adopted.
- **Superseded:** a later ADR replaces it; retain a link to the replacement.

## Required sections

Each ADR includes:

1. Title and status.
2. Context and the question being decided.
3. Verified evidence with source links, revisions, commands, and results where applicable.
4. Alternatives considered, with tradeoffs and blockers.
5. Decision and confidence, or a clear statement that no decision is possible yet.
6. Consequences and unresolved risks.
7. Links to related issues, roadmap phases, and superseding ADRs.

Do not turn an assumption or mock result into a verified compatibility claim.
